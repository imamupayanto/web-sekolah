1Bagaimana Vibe Coding Bekerja

Dari "saya mau begini" sampai jadi program — tanpa harus hafal sintaks.

Definisi paling sederhana

Vibe coding adalah cara membuat program dengan menjelaskan apa yang Anda inginkan dalam bahasa manusia kepada AI, lalu AI yang menuliskan kodenya. Anda fokus pada hasil dan rasa ("vibe"-nya) — bukan pada detail teknis penulisan kode.

Istilah ini dipopulerkan sekitar awal 2025 oleh Andrej Karpathy, yang menggambarkannya kira-kira sebagai: "Anda menyerah pada vibes, lupakan bahwa kodenya ada, dan tinggal lihat apakah hasilnya jalan." Intinya: peran Anda bergeser dari penulis kode menjadi pengarah dan penguji.

Analogi: memesan makanan vs memasak sendiri

Coding tradisional itu seperti memasak: Anda harus tahu bahan, takaran, urutan, dan suhu. Vibe coding itu seperti memesan ke koki: Anda bilang "saya mau nasi goreng, jangan pedas, tambah telur", koki yang meracik. Tugas Anda: mendeskripsikan pesanan dengan jelas, mencicipi, lalu bilang "kurang asin" sampai pas.

Konsekuensinya juga sama: kalau pesanan Anda kabur, hasilnya kabur. Dan Anda tetap perlu mencicipi — koki tidak tahu selera Anda kalau tidak dikasih tahu.

Kenapa AI bisa menulis kode?

Model AI seperti Claude atau ChatGPT dilatih dengan jumlah teks yang sangat besar, termasuk jutaan baris kode program beserta penjelasannya. Dari situ ia mempelajari pola: kalimat seperti "buat tombol berwarna biru" biasanya berpasangan dengan potongan kode tertentu.

Jadi AI tidak "mengerti" seperti manusia dan tidak menjalankan program di kepalanya. Ia memprediksi kode yang paling masuk akal berdasarkan pola yang pernah dilihatnya. Ini penting dipahami, karena menjelaskan dua sifatnya sekaligus:

Kelebihannya

Sangat cepat dan andal untuk hal-hal yang umum dan sering ditulis orang — halaman web, formulir, tampilan standar. Kode seperti ini sudah "ribuan kali" ada dalam data latihannya.

Kelemahannya

Bisa mengarang dengan percaya diri (halusinasi) saat diminta hal yang jarang atau sangat spesifik. Kodenya terlihat rapi dan meyakinkan, tapi belum tentu jalan. Karena itu menguji hasil itu wajib.

Siklus kerja vibe coding

Vibe coding bukan sekali jadi. Ia berputar dalam lingkaran kecil yang diulang sampai hasilnya sesuai:

Langkah 1
Niat
Tentukan dulu di kepala: saya mau bikin apa, untuk siapa, isinya apa saja.
Langkah 2
Prompt
Tuliskan niat itu ke AI sejelas mungkin — semakin konkret, semakin tepat hasilnya.
Langkah 3
AI Menulis Kode
AI menghasilkan kode lengkap. Anda tidak harus paham setiap baris, tapi jangan buta total.
Langkah 4
Jalankan & Lihat
Buka hasilnya. Ini bagian terpenting: lihat dengan mata sendiri, jangan percaya begitu saja.
Langkah 5
Koreksi
"Warnanya terlalu gelap", "tombolnya kekecilan" → kirim balik. Ulangi dari langkah 3.
Kunci utamanya ada di langkah 5 Pemula sering berhenti di langkah 3 dan kecewa karena hasil pertama tidak sempurna. Padahal hasil pertama memang tidak pernah sempurna — bahkan bagi yang sudah ahli. Kekuatan vibe coding justru ada pada kecepatan mengulang: revisi ke-5 bisa selesai dalam 3 menit, bukan 3 jam.

Dua baris terakhir sengaja ditebalkan. AI mempercepat pengerjaan, tapi tidak memindahkan tanggung jawab. Kalau webnya salah, yang menanggung tetap Anda.

Kapan vibe coding cocok, kapan hati-hati

Sangat cocok untuk

  • Halaman web sederhana, portofolio, undangan
  • Prototipe cepat untuk menunjukkan ide
  • Belajar — minta AI menjelaskan kodenya
  • Tugas berulang: rapikan data, ubah format
  • Proyek pribadi yang risikonya kecil

Perlu hati-hati untuk

  • Sistem yang menyimpan data pribadi orang lain
  • Apa pun yang berhubungan dengan uang/pembayaran
  • Aplikasi besar dengan banyak bagian saling terkait
  • Hal yang butuh keamanan serius
  • Kode yang akan dipakai orang banyak tanpa diperiksa ahli

Aturan praktis: semakin besar kerugian bila kodenya salah, semakin perlu manusia yang paham memeriksanya. Untuk belajar dan membuat web sederhana seperti di materi ini — risikonya nyaris nol, jadi silakan bereksperimen sebebas-bebasnya.

2Vibe Coding Khusus HTML

Membuat website sederhana dari nol, hanya dengan mengetik permintaan.

Kenapa HTML adalah tempat terbaik untuk memulai

Dari semua jenis coding, HTML adalah yang paling ramah untuk vibe coding pemula. Alasannya:

Hasilnya langsung terlihat

Tidak perlu paham kode untuk menilai. Buka di browser, kalau tampilannya bagus berarti berhasil.

Tanpa instalasi

Tidak perlu install program apa pun. Cukup satu file dan browser yang sudah ada di komputer Anda.

Aman untuk salah

HTML tidak bisa merusak apa pun. Salah? Hapus, minta lagi. Tidak ada yang hilang.

Satu file, selesai

Tampilan, gaya, dan interaksi bisa muat dalam satu berkas .html. Tidak ada struktur folder rumit.

AI sangat jago di sini

HTML adalah kode yang paling banyak ada di internet, jadi AI paling terlatih di bidang ini.

Mudah dibagikan

Kirim file-nya ke siapa pun, langsung bisa dibuka. Tidak perlu server.

Alur lengkap: dari ide ke web jadi

  1. Tulis permintaan ke AI — jelaskan halaman apa yang Anda mau.
  2. Minta dalam satu file HTML utuh — ini kalimat ajaibnya, jangan lupa.
  3. Salin seluruh kodenya — dari <!DOCTYPE html> sampai </html>.
  4. Tempel di Notepad (Windows) atau TextEdit mode plain text (Mac).
  5. Simpan dengan nama index.html — pastikan akhirannya .html, bukan .txt.
  6. Klik dua kali file-nya — otomatis terbuka di browser. Website Anda sudah jadi.
  7. Belum pas? Minta revisi — lalu ulangi langkah 3–6.
Cara lebih cepat lagi Pakai editor mini di bagian Praktik Langsung di halaman ini. Tempel kodenya di kotak kiri, hasilnya langsung muncul di kanan — tanpa perlu menyimpan file sama sekali.

Resep prompt yang bagus: 5 bahan

Prompt yang baik itu bukan yang panjang, tapi yang lengkap unsurnya. Ini lima bahan yang sebaiknya ada:

BahanPertanyaan yang dijawabContoh
1. ApaHalaman jenis apa?"halaman profil pribadi"

Bandingkan sendiri

✕ Prompt lemah

Buatkan website.

Terlalu kabur. AI akan menebak, dan tebakannya kemungkinan besar bukan yang Anda bayangkan.

✓ Prompt kuat

Buatkan satu file HTML lengkap untuk halaman profil pribadi saya.

Isinya: foto bulat di atas (pakai gambar placeholder), nama "Imam", satu kalimat deskripsi, bio 3 kalimat, daftar 3 keahlian dalam bentuk kartu, dan tombol kontak email di bagian bawah.

Gayanya: modern dan bersih, dominan putih dengan aksen biru, sudut membulat, banyak ruang kosong.

Teknis: CSS ditulis di dalam file yang sama (jangan file terpisah), harus rapi juga dibuka di HP, tanpa library eksternal.

Pakai teks contoh dulu, nanti saya ganti sendiri.

Kalimat-kalimat yang sebaiknya selalu Anda pakai

Untuk memastikan hasilnya bisa langsung dipakai:

"Buat dalam satu file HTML lengkap" "CSS-nya di dalam file yang sama" "jangan pakai library dari internet" "tampilkan kode utuhnya, jangan dipotong" "pastikan rapi juga di layar HP"

Untuk merevisi:

"warnanya terlalu mencolok, buat lebih lembut" "tulisannya kekecilan, perbesar" "tambahkan bagian X di bawah bagian Y" "jaraknya terlalu rapat, beri ruang lebih" "kirim ulang kode lengkapnya setelah diubah"

Untuk belajar sambil jalan:

"jelaskan setiap bagian kodenya untuk pemula" "bagian mana yang harus saya ubah kalau mau ganti warna?" "beri komentar di setiap baris penting"

Kesalahan paling sering: "kirim ulang kode lengkapnya" Saat merevisi, AI kadang hanya mengirim potongan yang berubah. Kalau Anda pemula, ini membingungkan karena tidak tahu harus ditempel di mana. Selalu tambahkan "kirim ulang kode lengkapnya dari awal sampai akhir" di setiap permintaan revisi.

Empat masalah umum & solusinya

Yang terjadiPenyebab biasanyaYang harus dilakukan

Prinsip yang membedakan hasil bagus dan asal jadi

  • Mulai kecil, tambah sedikit demi sedikit. Minta kerangkanya dulu, baru tambah bagian satu per satu. Jangan minta 10 fitur sekaligus di prompt pertama — kalau ada yang salah, Anda tidak tahu yang mana.
  • Satu revisi, satu fokus. "Ubah warna jadi hijau" lebih mudah dieksekusi tepat daripada "ubah warna, geser menu, tambah footer, perbesar font" sekaligus.
  • Simpan versi yang sudah bagus. Sebelum minta perubahan besar, simpan file lama dengan nama lain (profil-v1.html). Kalau versi baru malah lebih jelek, Anda bisa kembali.
  • Buka hasilnya, jangan cuma dibaca kodenya. Kode yang "kelihatan benar" tapi tidak pernah dijalankan adalah jebakan paling umum dalam vibe coding.
  • Sisihkan waktu untuk paham sedikit. Anda tidak perlu jadi programmer. Tapi kalau tahu sedikit HTML (bagian 3 di bawah), Anda bisa mengubah teks dan warna sendiri tanpa bolak-balik ke AI — jauh lebih cepat.

3Apa Itu HTML & Cara Kerjanya

Dasar yang benar-benar perlu Anda tahu — tidak lebih, tidak kurang.

HTML itu apa?

HTML singkatan dari HyperText Markup Language. Perhatikan kata terakhirnya: Markup, bukan Programming. HTML bukan bahasa pemrograman — ia tidak menghitung, tidak mengambil keputusan. Tugasnya cuma satu: memberi tanda pada teks agar browser tahu setiap bagian itu apa.

Analogi: menandai buku dengan stabilo

Bayangkan Anda punya selembar kertas berisi tulisan polos. Anda lalu menandainya: bagian ini judul, ini paragraf, ini daftar, ini gambar. Nah, tanda-tanda itulah HTML. Browser membaca tanda tersebut lalu menampilkan judul dengan huruf besar tebal, paragraf dengan huruf biasa, dan seterusnya.

Jadi HTML tidak "membuat" tampilan — HTML menjelaskan makna, dan browser yang menerjemahkannya jadi tampilan.

Tiga bersaudara dalam sebuah website

Setiap website dibangun dari tiga hal yang bekerja bersama:

HTML — Kerangka

Menentukan apa isinya: judul, teks, gambar, tombol. Seperti tulang dan organ pada tubuh.

CSS — Penampilan

Menentukan seperti apa tampilannya: warna, ukuran, jarak, tata letak. Seperti pakaian dan gaya rambut.

JavaScript — Perilaku

Menentukan apa yang terjadi saat diklik atau diketik. Seperti gerakan dan reaksi tubuh.

Untuk membuat web sederhana, HTML + sedikit CSS sudah lebih dari cukup. JavaScript baru diperlukan kalau halaman Anda harus "bereaksi" pada pengguna.

Anatomi sebuah tag

Semua HTML dibangun dari tag — potongan kode di dalam kurung siku < >. Sebagian besar tag berpasangan: satu pembuka, satu penutup.

<p class="intro">Halo dunia</p>
tag pembukamulai di sini
atributinfo tambahan
isiyang terlihat pengguna
tag penutupada garis miring /
  • Tag pembuka — menandai awal, contoh <p>
  • Isi — teks atau elemen lain yang ada di dalamnya
  • Tag penutup — sama seperti pembuka tapi ada garis miring: </p>
  • Atribut — informasi tambahan yang ditulis di tag pembuka, misalnya alamat gambar atau tujuan link

Beberapa tag tidak punya penutup karena tidak punya isi — misalnya <br> (ganti baris) dan <img> (gambar). Ini disebut tag tunggal.

Kerangka wajib setiap halaman HTML

Setiap file HTML punya struktur dasar yang selalu sama. Hafalkan bentuknya saja, jangan hafalkan hurufnya:

<!-- Memberi tahu browser: ini file HTML modern -->
<!DOCTYPE html>
<html lang="id">

<head>
  <!-- Info di balik layar, TIDAK terlihat di halaman -->
  <meta charset="UTF-8">
  <title>Judul di Tab Browser</title>
</head>

<body>
  <!-- Semua yang TERLIHAT ditulis di sini -->
  <h1>Halo, Dunia!</h1>
  <p>Ini paragraf pertama saya.</p>
</body>

</html>

<head>Info untuk browser: judul tab, pengaturan huruf, gayaTidak

Cara browser membaca HTML (langkah demi langkah)

Tahap 1
Menerima
Browser mengambil file HTML — dari komputer Anda atau dari server di internet.
Tahap 2
Membaca Urut
Dibaca dari atas ke bawah, seperti membaca buku. Itu sebabnya urutan tag menentukan urutan tampilan.
Tahap 3
Menyusun Struktur
Setiap tag diubah jadi "kotak" yang saling bersarang — membentuk peta isi halaman.
Tahap 4
Menerapkan Gaya
Aturan CSS ditempelkan ke tiap kotak: warna apa, ukuran berapa, di mana posisinya.
Tahap 5
Menggambar
Semuanya digambar ke layar. Inilah halaman yang Anda lihat. Prosesnya di bawah 1 detik.
Konsep bersarang (nesting) Tag bisa berada di dalam tag lain, seperti kotak di dalam kotak. Aturannya: yang dibuka terakhir harus ditutup lebih dulu.

Atribut: informasi tambahan pada tag

Atribut ditulis di dalam tag pembuka dengan pola nama="nilai". Empat yang paling sering muncul:

Menambahkan CSS: dari polos jadi menarik

HTML polos tampilannya sangat sederhana. CSS ditambahkan di dalam <head> menggunakan tag <style>:

<head>
  <style>
    /* Aturan untuk seluruh halaman */
    body {
      font-family: Arial, sans-serif;   /* jenis huruf */
      background: #f4f6fa;             /* warna latar  */
      padding: 40px;                  /* jarak tepi   */
    }

    /* Aturan khusus untuk semua tag h1 */
    h1 {
      color: #1f5fd6;                  /* warna teks   */
      font-size: 32px;                /* ukuran huruf */
    }
  </style>
</head>

Polanya selalu sama: pilih elemennya (body, h1) → buka kurung kurawal → tulis daftar aturan sifat: nilai; → tutup kurawal.

Yang cukup Anda ingat dari CSS color = warna teks · background = warna latar · font-size = ukuran huruf · padding = ruang di dalam · margin = jarak di luar · text-align: center = rata tengah. Dengan enam ini saja Anda sudah bisa mengubah tampilan hasil vibe coding tanpa bertanya lagi ke AI.

4Praktik Langsung

Ubah kode di kotak kiri, hasilnya berubah seketika di kanan. Tidak ada yang bisa rusak — silakan berantakan sepuasnya.

Editor HTML — coba ganti tulisannya, lalu lihat kanan

Tantangan kecil untuk Anda

  1. Ganti tulisan di dalam <h1> dengan nama Anda sendiri.
  2. Ubah nilai color pada h1 menjadi green atau #e63946.
  3. Tambahkan satu <li> baru ke dalam daftar yang ada.
  4. Hapus salah satu tag penutup (misal </p>) — perhatikan apa yang kacau. Lalu kembalikan.
  5. Klik Halaman Profil untuk melihat contoh hasil vibe coding yang sudah jadi, lalu bongkar-pasang isinya.
Langkah berikutnya Buka AI favorit Anda, salin contoh prompt kuat di Bagian 2, ganti isinya sesuai kebutuhan Anda, lalu tempel hasil kodenya ke editor di atas. Itulah satu siklus vibe coding yang utuh — dan Anda sudah menyelesaikannya.
